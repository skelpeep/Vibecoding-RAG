# 阶段六、七设计与最终视觉复核

2026-10-22，沿用 design-taste-frontend 的 app-screen 流程。framed-sheet，seed **993422931**，未重抽。蓝灰纸夹外框、白色工作纸、开放书页标记；IBM Plex Sans + Noto Sans SC 本地字体，数据主色 #1b6c80。原设计依据见 decisions.md；此文替代其中“后续模块未实现”的历史状态。

## 数据与工作

1. 管理员查看真实问答请求数、UV、当前知识量、供应商已知 Token、毫秒耗时。
2. 时间按北京时间的自然日或周划分，所有统计和趋势使用同一接口快照。
3. 访问、耗时与 Token 数量来自 MySQL 日志；当前低量演示数据不补造增长或同比。
4. 问题榜与知识标题依当前正文权限过滤，组织管理员不自动看到私有文本。
5. 知识管理员每天处理待审核 FAQ、已发布答案与未解决缺口。
6. 推荐 FAQ 显示原问题、答案、频次、实际缓存次数与完整依赖来源。
7. 审核、编辑后重审、撤回是独立真实操作；旧来源失效时明确脱敏。
8. 缺口显示原问题、次数与关联知识，草稿创建不会自动标记解决。
9. 原问题验证回答后直接确认补全，避免用户手工寻找请求编号。
10. 使用桌面处理队列、手机查看/临时补全；手机导航收起，操作和内容顺序重排。
11. 空队列保持简短业务说明与真实下一步，不造假条目填满页面。
12. 所有演示内容可在 stage6/http.json 和 ui/gap-draft.json 找到；它们是虚构规范的真实系统记录，不是运营业绩。

## 页面首要问题

| 页面 | 首要问题与动作 |
| --- | --- |
| 登录 | 如何用个人身份进入组织？填写账号并登录。 |
| 用户 / 角色 / 部门 | 谁可登录、能做什么、属于哪里？真实表格、树和权限配置。 |
| 个人中心 | 我的身份与权限是什么？身份关系带及资料表单。 |
| 知识列表 / 导入 | 哪些知识可读，哪些任务需处理？筛选、导入、查看进度。 |
| 编辑 / 详情 | 内容、版本与阅读范围是否正确？编辑、激活发布、授权。 |
| 问答 | 我能依据哪些知识得到回答？提问、打开来源、识别缓存或权限提示。 |
| 看板 | 知识库实际被怎样使用？请求量先读，日期过滤，三种趋势与榜单。 |
| FAQ 推荐 | 哪些重复回答值得发布？候选内容与来源在同一行，直接审核。 |
| 已发布 FAQ | 当前哪些答案生效？编辑后重审、撤回、失效说明。 |
| 知识缺口 | 哪些问题仍未获得依据？创建草稿、验证原问题、确认解决。 |

特色元素从身份关系带扩展成“有依据回答 / FAQ 命中 / 依据不足 / 权限受限 / 失败与取消”结果带，以及 FAQ 的全来源列表。FAQ 命中是有依据回答的子集，不能相加。主图采用技能 charts.js 的本地副本；仅为无相邻观测值的孤立数据增加圆点，null 仍为缺口，未修改检查器。

布局：桌面有效工作宽度约 1154px，三趋势图各 (1154−2×24)/3，榜单与说明使用两列 (1154−24)/2，共用边缘。平板前两图并排、耗时图占整行；手机全改单列，指标两列，单个末项保持正常尺寸。

## 七项截图评审

1. **主问题与顺序**：看板最先看到访问次数，其后是可靠回答结果；审核与缺口首先出现真实问题及操作。登录表单、知识正文、问答内容仍为对应屏幕重心。
2. **边缘与空间**：标题、过滤器、数据和列表共用左右边；没有整页横溢。短部门树与空推荐队列有留白，这是当前真实内容密度。没有拉长卡片去填满空间。
3. **颜色与产品面貌**：浅蓝灰 L 框架、书页标记与本地字体一致；青色用在数据、来源和选中提示，主要提交按钮近黑，失效/错误用状态色。
4. **数值一致性**：访问、UV、Token 已通过日志重算；分布计数等于有耗时的终态数；FAQ 命中包含在成功回答中。截图随验收请求增长，跨时间截图不要求数值相等。数字使用 tabular-nums、千分位和明确单位。
5. **零与缺失**：无请求为 0；无耗时为缺口和“当前范围暂无可用数据”；只有一天有耗时时显示孤立点。未知/部分 Token 单独说明。没有伪造增长率或队列徽标。
6. **图例与标签**：单序列无多余图例，三条趋势的标题分别说明访问、Token、毫秒；坐标刻度取整齐值。三个宽度无标签碰撞。耗时分布条和数量一一对应。
7. **手机**：导航收起，过滤器可换行，FAQ 操作落在正文之后；弹窗在 390px 可阅读并点击取消/保存。已完成手机缺口→草稿→真实构建→发布→原问题→确认补全全链路。
