# 阶段三设计方向

2026-10-22。技能：design-taste-frontend，app-screen 分支。方向 framed-sheet，seed 993422931。候选 framed-sheet / accent-ladder，选择前者：组织管理员长期处理身份、组织和权限，浅色框架与正文表格能清楚分隔导航和工作区。未重抽。

## 数据与工作清单

1. 产品名称“知识库管理平台”；场景为组织内部知识访问管理，桌面长期工作，手机临时处理。
2. users：用户名、姓名、直属部门、多个角色、启停状态和更新时间；当前真实种子 7 人，分页 20 人，可增长。
3. departments：树、编码、负责人、直属成员数；当前 4 部门，部门访问不自动向下继承。
4. roles：角色名称、编码、描述、菜单和操作授权；当前 5 角色，权限数量由 API 返回数组计算。
5. 当前身份：认证接口返回部门/角色/权限；展示身份关系，不能以角色名称推测正文访问。
6. 系统管理员的主要工作是创建/调整用户、角色与部门，知识管理员与普通用户只有各自已授予的入口。
7. 用户页首要动作：新增用户；行内编辑与独立角色、状态、密码操作各自鉴权。
8. 角色页首要动作：配置角色权限；权限菜单与操作独立选中，明确选中数量与实际结果。
9. 部门页首要动作：维护层级与人员归属；树选择后显示直属成员，不能把下级人数算作直属人数。
10. 个人中心：查看当前身份、更新资料、修改密码；密码变更重新登录。
11. 所有列表/汇总来自真实 API。种子来源 atguigu/business/seed.py；前端不硬编码 7/5/4，也不另造运营数字。
12. 无数据/错误/停用/权限不足均保持工作区结构；不存在的后续功能清楚说明未开放。

## 页面的问题、动作与布局

| 页面 | 首要问题 | 主要动作 | 布局 |
| --- | --- | --- | --- |
| 登录 | 我如何以自己的账号进入？ | 登录 | 品牌与组织关系示意 / 简短登录表单 |
| 用户 | 谁能登录，属于哪个部门和角色？ | 新增用户 | 状态页签、搜索/部门过滤、身份表格、编辑弹窗 |
| 角色 | 这个角色能做什么？ | 配置权限 | 左侧角色列表，右侧按模块分组的真实权限选择 |
| 部门 | 部门层级与直属成员是谁？ | 新增部门 | 部门树 + 选中部门资料/直属成员 |
| 个人中心 | 我的身份与操作权限是什么？ | 保存资料 | 身份关系带、资料表单、独立密码表单 |
| 后续模块 | 此入口何时可使用？ | 返回可用工作区 | 简洁说明与模块布局预留，无假业务控件 |

产品的脸：知识档案的蓝灰纸夹外框（#f4f7f8），白色 sheet。标记为三片相接的开放书页线条，使用 #1b6c80，不用方块字母。特色元素为身份关系带：本人 → 直属部门 → 角色 → 操作范围，在个人中心及角色权限摘要出现；解释权限结果，不模拟正文授权。

字体：本地加载 IBM Plex Sans 400/500/600，中文使用 Noto Sans SC 可变字重（同为无衬线）；不使用第三套 mono。数字 tabular-nums。后者补齐抽取字体不含的中文字形。颜色和排版以 direction.json 为准，外框色按技能允许的产品脸映射；其他 token 沿用。

布局算式：1440 = 228 sidebar + 8 right inset + 1204 sheet；sheet 内 2×24 padding 后有效宽 1156（另减边框 2）。双栏 = 280 + 24 gap + 剩余；768 折叠导航并保留 24 gutters；390 使用 16 gutters，单区域优先，菜单为弹层。初始空框截图在 shell/，业务截图在各页面目录。

后续布局：知识列表沿用表格/筛选；文档详情使用正文 + 访问范围侧栏；问答使用会话列表 + 对话主区；看板按真实日志的指标和趋势安排；FAQ 使用候选队列 + 审核详情。当前不实现这些业务或虚构数字。
