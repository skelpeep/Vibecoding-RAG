# 阶段三验收与设计评审

日期：2026-10-22。范围：前端框架、认证/个人中心、组织管理与共用交互。真实接口为 8102，Vue 开发入口为 5183，MySQL 沿用阶段二。没有新增知识、RAG、FAQ 或运营统计业务。

## 设计方向

使用 `design-taste-frontend` 的 app-screen 流程，候选后选择 **framed-sheet / seed 993422931**，无重抽。设计清单与各页问题记录在 `.taste-skill/decisions.md`，原始方向为 `direction.json`。

蓝灰外框 `#f4f7f8` 与白色工作页承载组织档案；228px 导航、24px 桌面间距、16px 手机间距、近黑主按钮与单一青色 `#1b6c80`。产品标识是开放书页线条。特色元素为“本人 → 直属部门 → 角色 → 操作权限”身份关系带；角色页另显示实际选中数量，明确菜单、操作与正文访问的不同作用。

本地字体为 IBM Plex Sans 400/500/600，中文回退 Noto Sans SC Variable，数字 tabular-nums。CDP `CSS.getPlatformFontsForNode` 确认中文标题和英数实际使用这两个自定义字体，详见 `evidence/stage3/screens.json`；不是只检查 CSS 声明。

| 页面 | 优先回答的问题 | 首要操作 |
| --- | --- | --- |
| 登录 | 如何以自己的组织账号进入？ | 登录 |
| 用户 | 谁可以登录，属于哪个部门和角色？ | 新增/调整成员 |
| 角色 | 角色能进入哪些页面、执行哪些操作？ | 配置并保存权限 |
| 部门 | 组织层级与直属成员是谁？ | 维护部门/人员归属 |
| 个人中心 | 我的身份是什么，如何更新资料和密码？ | 保存资料/更新密码 |
| 未开放/拒绝/失败 | 当前为什么不能继续，下一步是什么？ | 返回可用页/重试 |

所有工作数据来自真实 API，示例来源是阶段二 `atguigu/business/seed.py` 的 7 位用户、4 个部门、5 个角色；前端无独立假数据或硬编码总数。正式使用时由管理员维护自己的组织。截图中的“阶段三验收”记录仅是明确标识的临时联调数据，测试结束已清理。

## 三轮内视觉评审

先检查 `.taste-skill/shell/` 的桌面/手机空框，再接真实数据。第一轮发现辅助字号过小、权限页过长与平板表头断行；第二轮提高状态/标签/表头至 13px，权限分组折叠保留计数，补齐焦点和选项失败保护；第三轮修复手机部门成员姓名挤窄，用两行网格保持姓名、状态和角色完整。手机交互目标 44px，状态文案保留，所有字段可见。

逐张打开或通过带原文件名的联系表查看所有最终 inspector 的 fold/page 截图：users、roles、role-detail、departments、department-detail、profile、login、module、forbidden，共 54 张，拼图在 `.taste-skill/review/`；另核对 18 张页面截图及 `interactions/`、`states/` 的错误、空、加载和表单图。动画中的表单截图已替换为完整渲染后的版本。下表是 app-screen 七项评审。

| 评审项 | 结论与修正 |
| --- | --- |
| 1. 主问题/阅读顺序 | 用户表、角色权限、部门成员为最大内容；身份关系先于资料/安全设置，标题与首要操作在上方。角色组支持折叠，长表单仍可正常滚动。 |
| 2. 边缘/栅格/留白 | 主区统一对齐，列表与详情顶端对齐，不强行拉伸成员卡。手机成员由 flex 改两行 grid，解决姓名窄列逐字折行。工作外框保留全高，稀疏内容的留白解释如下。 |
| 3. 颜色/产品辨识 | 蓝灰纸夹外框、书页标识、青色权限选中；主要文字近黑，头像仅淡色区分身份，无渐变、发光或图标彩块。 |
| 4. 数量/对齐 | 用户总数与筛选一致，部门树直属人数 1+3+2+1=7；普通角色 3 项知识操作+2 项问答=5；系统角色 25 项含 3 菜单，个人中心显示 22 项操作。数字列右对齐且等宽。 |
| 5. 零/缺失 | 无操作角色显示 0 项；空搜索显示共 0 位；无部门/角色显示破折号，负责人缺失显示未设置。没有把未知运营指标显示成 0。 |
| 6. 图例/碰撞 | 本阶段无统计图/图例。状态有文字和小圆点，权限分组计数有单位；平板表头及移动成员姓名碰撞均已修正。 |
| 7. 手机 | 导航折叠并有焦点圈定、Escape 和返回焦点；用户表改列表，角色/部门一次显示一个区域，表单可滚动到保存，详情加载完再截图，无整页横溢。 |

保留的 WARN 未通过 allow 参数绕过：

- lint shadow 1 处：只在真实悬浮行菜单使用弱阴影，符合浮层规则。
- lint eyebrow 3 处：`.section-label` 是角色/部门列表的语义标题及计数，不是营销页装饰眉题；源代码选择器被重复计数。
- 部门列表/详情各 2 个、未开放页/拒绝页各 2 个 hero-void/panel-void：识别到的是固定全高工作外框底部，内部内容按真实数量自然收缩；为保持同一工作区导航及页面位置，保留框架留白，不补造业务数据。
- profile 的 no-data-hue 1 个：检测器将身份关系 SVG/箭头判作图表，页面实际无统计图；操作数用中性文字，避免无依据的状态着色。

## 后续边界

阶段四沿用本方向与共用表格/筛选/详情/表单，新增知识单元、四维数据授权、版本、附件与导入中心；阶段五完成会话与流式鉴权问答；阶段六按真实日志做指标和 FAQ 审核队列。当前未开放页不能当作这些功能已完成。

本轮以 Chrome 桌面浏览器的三种 viewport 验收；未进行实体手机、Safari、长时负载或大规模组织数据验证。多页控件已实现，当前真实种子不足 20 位，本轮验证了单页边界及筛选，未声称大数据分页性能验收。生产部署、TLS、正式账号替换与长期运行属于后续集成交付。
